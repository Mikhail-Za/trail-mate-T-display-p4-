# Native Meshtastic nonce repair

Current authority: user explicitly stopped Spark use during its benchmarks and selected GPT implementation plus Anthropic review. Astra orchestrates and verifies; Conductor Sol workers implement after the Crucible plan gate. Incremental commits/pushes remain authorized. Current implementation baseline d302b20; earlier local-worker authority is superseded.

## Observed facts and decisions

The native adapter uses stable eFuse sender identity and an in-memory counter beginning at 1. sendText allocates independently; sendEncodedPayload allocates or accepts caller IDs. Existing wire nonce is little-endian packet ID (8 bytes), sender (4), block counter (4). All four direct sendEncodedPayload callers must use one allocator. User confirms private keys are exclusive to Trail Mate. Channel configuration loads before adapter applyConfig. Eight slots include disabled channels.

Use the accepted Spark reserve-before-use allocator, with a single process-wide serialized owner in the native radio layer. Persist one versioned NVS blob in a dedicated tm_pkt_ids/state_v1 key before issuing IDs. Record magic/version, sender identity, exclusive uint64 high-water (1..2^32), and fingerprints of up to eight legacy explicit keys. Never write raw keys. Initialization captures the exact effective private AES key bytes, INCLUDING disabled slots, before any TX when the record is absent. Use normalizeMeshtasticChannelKeyLen exactly as updateChannelKeys does, then expandChannelPsk. Empty keys and the known public short-PSK family are excluded from legacy blocking. That family is every 16-byte key sharing the first 15 bytes of kDefaultPskBytes (the final byte spans all 256 expansions). A zero-length outgoing PSK remains an allowed open channel and skips hashing. No arbitrary raw-length or 32-byte-buffer hashing. SHA-256 errors, malformed records, wrong sender, open/read/set/commit errors fail closed. Latch storage/hash failures for this boot; never silently reinitialize a malformed existing record. A reboot skips the whole previously reserved range. Reject zero sender identity, packet-ID wrap and exhaustion. Native transmissions always auto-allocate; sendAppData packet_id is an optional hint and will be ignored, as the inherited native sendTextWithId already ignores forced IDs. No caller hint can advance or exhaust the persistent counter. A failed transmission consumes its allocated ID.

Migration: block outgoing payloads encrypted with captured legacy keys, regardless of channel slot, name, enabled state, or reimport. Receive remains available. Operators must provision fresh private channel keys on all participating Trail Mate units; changing a name or passphrase spelling without changing the derived key is insufficient. Keys imported after migration must be fresh with respect to this sender's pre-upgrade traffic. Historic removed keys cannot be reconstructed.

NVS erasure and old backup restore require fresh private keys. Full backup rollback is not reliably detectable without a separate monotonic hardware authority; this repair does not claim anti-rollback protection. Do not flash an older counter implementation with these new keys. Public/default PSKs provide no confidentiality. These are deployment constraints, not claims that existing recorded traffic becomes secure.

## Implementation assignments

1. Conductor Sol worker: new native packet-ID storage header/implementation only, reusing the immutable allocator. Parent supplies frozen tests with observable NVS/SHA substitutes. Two functions initializePacketIds(node, config) and allocatePacketId(node, psk, len, out). One static mutex and owner; no public constructible store or test reset APIs. Fixed 273-byte blob: TPI1 (4), node LE32 (4), high-water LE64 (8), count (1), eight SHA256 fingerprints (256). Validate zero unused fingerprint bytes; successful reservations update only the bound.
2. Conductor Sol worker: adapter integration in sendText, sendEncodedPayload and applyConfig; remove next_packet_id_. Allocate only inside sendEncodedPayload; give it optional output-ID pointer. Ignore packet_id hints and always call the native allocation API without a requested ID. Text payload encoder's unused ID argument can be zero. Reject disabled/out-of-range channels before encryption. No wire format or crypto algorithm changes. Parent integrates source list and CI check as small chores.

3. Conductor Sol worker: fail-closed channel loading in NvsChannelBlobStore::load, loadChannelConfigFromNvs and IdfChatFacade::initialize. Distinguish absent namespace/key from open/read/decode errors using direct NVS status. Only absence may migrate existing scalar defaults. Validate bounded/exact blob size, 1..8 count and codec result before copying any records; the existing codec can return a count larger than max without filling outputs. Stop facade initialization before runtime creation when load fails. Change the bool loader contract to true on a successful stored load OR absent-storage migration, false on error; its sole caller is the facade. Preserve the current save path and all unrelated settings. Supply a production-body host regression with NVS errors and malformed/oversized counts.

## Prior Astra plan review (independent Crucible gate now required)

Material pitfalls resolved in the plan: capture disabled keys; key identity rather than slot/name; reserve before any TX; a single owner across adapter instances; no double allocation for text; output ID zero on allocation failure; latch uncertain storage errors; no claim that software-only NVS detects full restore rollback. State is not reset by channel changes. The stored high-water never resets on rekey or exhaustion.

Astra recon addendum: NvsChannelBlobStore currently collapses missing/read/decode failure to zero; facade ignores loader return. An upgrade-time read error could therefore commit an incomplete legacy fingerprint list and later allow recovered old private keys. Assignment3 closes this path. It also bounds the codec count before the current caller could copy uninitialized records for count>8.
