# Team legacy key-distribution containment

Baseline bebf9a8. User authorizes audit/security repairs, GPT workers, Anthropic review, commits and pushes. Spark is excluded. This is a bounded first patch, not a claim of secure pairing, leader authentication or safe removal. The complete protocol acceptance remains SECURITY-IMPLEMENTATION-PLAN.md.

Observed: TeamService::processIncoming invokes sink_.onTeamKeyDist and setKeysFromPsk for plaintext or group-encrypted KeyDist. Neither has authenticated leader provenance. The UI separately consumes pairing KeyDist. Both sendKeyDist variants expose new keys to an excluded member (old group key or plaintext), while confirmKick still switches local keys even if sends fail. Existing sender IDs/group membership cannot provide per-peer leader authentication. Native IDF pairing has no retained per-peer secret and no proof-of-password confirmation; replacing its protocol needs separate design.

Immediate behavior: refuse legacy TEAM_MGMT KeyDist ingress regardless of encryption, team, key epoch or payload. No key derivation, KeyDist event, member-roster or persistence mutation from that message. Existing general incoming observers remain called, and separate TEAM_PAIR_APP pairing remains explicitly out of scope. Disable both public sendKeyDist functions before serialization/logging/encryption/transmission, returning new SendError::SecurityUnavailable. Also refuse sendKeyRequest and ignore its ingress so UI cannot promise recovery or trigger futile automatic response loops. Keep API signatures for callers and future versioned replacement. Ordinary Team chat/position/status paths remain unchanged; their separate auth/replay risks are not declared fixed.

UI: confirmKick must return an explicit SecurityUnavailable failure for an otherwise valid leader/member selection before any send, random generation, reducer mutation, key application or retry scheduling. Remove dead rotation implementation/helpers from that file, retaining public signature. Handle rejected confirm effects before state persistence/navigation in handle_kick_confirm; display a clear user-facing secure-removal-unavailable message. Map SecurityUnavailable for recovery to clear secure-key-update-unavailable wording. Clear/deny any pending legacy KeyDist retries before reading/copying PSK or calling ports, with no sent=true indication. Leave status retries functional. Do not add fake secure success, auto-regenerate keys, or tell users to use the still-insecure pairing path as a secure workaround.
